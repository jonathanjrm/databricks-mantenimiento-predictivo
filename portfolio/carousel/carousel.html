Turbofans do not fail on a schedule.
They degrade.

Fixed-interval maintenance replaces healthy parts and still misses the engine that is about to fail. The question a maintainer actually asks is simpler: how many cycles are left on this unit, and how sure are we?

Illustration

THE DATA

NASA C-MAPSS FD001: 100 engines run to failure for training, 100 truncated engines for testing, 21 sensors per cycle. A public simulation dataset, not fleet telemetry.

THE TARGET

Remaining useful life (RUL) in cycles at the last observed cycle of each test engine, plus a grounded answer when the maintainer asks the manual what to inspect.

WHAT THE AUDIT CHECKED

  • 20,631 train and 13,096 test rows match the official FD001 files; 0 nulls, contiguous cycles.
  • RUL label = last cycle minus cycle, clipped at 125: 0 discrepancies across 20,631 rows.
  • Rolling windows look backward only: 40 truncation tests, 0 leaks.

PANDAS VS SPARK

  • 7 constant sensors dropped, 14 kept; value, mean and std over 5 and 10 cycles, slope over 10, plus the cycle.
  • 170 column sums compared between the Spark pipeline and the pandas reference: max relative difference 2.4e-9.
  • Last-cycle rows of all 100 test engines: max absolute difference 3.7e-10.

HONEST READING

The test set also informed the champion rule, so 18.44 describes a frozen model on a seen set, not an independent error estimate. A by-engine protocol on train only gives 18.0 with a 1.2 spread over 200 random cuts, and the new promotion gate uses that validation (HGB 19.2 vs Ridge 22.1), never the test set.

NEAR FAILURE

With an actual RUL of 30 or less (25 engines) the model overestimates the remaining life by 5.5 cycles on average, and 6 of 26 low-RUL engines are shown as healthy. That is the unsafe direction, and the reason the dashboard labels every number a demo estimate that requires engineering review.

The dashboard never calls the endpoint: it reads the batch table written by 03_score with the same model and shows model version and scoring time. The endpoint is the independent path the audit used to cross-check every value.

09 / 10

What is verified, and what is not

VERIFIED

  • Data counts, labels and windows match FD001; Spark and pandas features agree to 1e-9.
  • Champion v1 reproduced bit for bit (RMSE 18.441849882005343) with the workspace library versions.
  • Endpoint invoked for all 100 engines: identical to the dashboard table, 0 mismatches.
  • No silent fallback: SQL failure is an explicit 503, a null prediction stays null.
  • RAG: 85-question held-out set, deterministic checks plus an independent judge model.
  • 142 automated tests, pip-audit and bandit clean, no secrets in tree or history.

LIMITATIONS

  • The FD001 test set is a seen set: it informed model selection, so no independent error estimate exists yet.
  • Uncertainty is not calibrated: RMSE is a typical error, not a prediction interval.
  • Near failure the model overestimates life by 5.5 cycles on average; 6 of 26 low-RUL engines show as healthy.
  • Predictions are batch scores at the last observed cycle, not live inference on telemetry.
  • The serving endpoint accepts null features without error (open finding, medium).
  • Assistant answers take 10 to 30 s and vary between runs at temperature 0.1.
