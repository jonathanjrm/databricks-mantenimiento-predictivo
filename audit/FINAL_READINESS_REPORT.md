## 4. Recommendation and result

The technical side is verified with evidence: data, model, endpoint, app, tests and security are in a publishable state and the audited code,
the README and the phase F materials are on GitHub (`main`, commit `c5f75fa`), with every figure traced to the audit reports
(`portfolio/SOURCES.md`). The 14 essential criteria are PASS; the open issues (D-12, D-02, B2.5, D-01, C-NV, D-04/06/08/11) are not critical for a portfolio publication and are declared in the README and in the posts.

**Final result: `PUBLICATION_READY`** (recomputed on 15 October after closing G-01), with these caveats:
1. the demo video is still not recorded (NOT_VERIFIED); the carousel and the case study do not depend on it;
2. before publishing or a demo, check that app and endpoint are started (`apps start`, `/api/health` ok, `bundle deploy -t dev` if the endpoint is missing): on 15 October the app stopped on its own again minutes after being used and the endpoint had disappeared once (D-12); the posts already declare that availability is not continuous;
3. the first run of the CI workflow after the push has not been checked (D-01);
4. the train-only promotion protocol has not been exercised in the workspace (B2.5) and the endpoint does not validate inputs (D-02);
5. this report and the README were published in a second commit after `c5f75fa` (see the history of `main`).

Readiness for a portfolio publication implies neither industrial certification nor continuous availability of the service.
